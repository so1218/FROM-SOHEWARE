# デバッグ

思った通りに動かないときに使う道具と、調べる順番です。

## まず見るところ

| 症状 | 見るところ |
| :--- | :--- |
| モデル・テクスチャ・音・エフェクトが出ない | 「開発用のエラー」ウィンドウ |
| 当たらない | シーン名のウィンドウの「コライダーを表示」で形と位置を確認 |
| 値が思った通りにならない | オブジェクトの `DebugGui` に値を出す。保存した値がコードより優先されていないか確認 |
| 落ちる | Visual Studio のデバッガ、`Dumps/` のクラッシュダンプ |
| 重い | 「全体のデバッグ情報・設定」の FPS、PIX |

## 開発用のエラー

モデル名の書き間違い、見つからないテクスチャ、登録していないキーの表示など、**開発中に直すべき間違い**があると、画面に「開発用のエラー」ウィンドウが出ます。
間違いの内容と、それを書いた場所 (ファイル名と行、または JSON のどの項目か) が表示されるので、そこを直してください。ゲームは止まりません。

自分のコードでも、同じ仕組みで間違いを知らせられます。

```cpp
#include "DevError.h"

if (spawnPoints_.empty())
{
    DevError::Report("出現位置が 1 つもない。EnemySpawner.json に SpawnPoints を足す");
}
```

同じ内容は何回呼んでも 1 回分として数えるので、毎フレーム呼ぶ場所に書いても構いません。内容はログにも残ります。

## ログ

```cpp
#include "Logger.h"

LOG_INFO("敵を {} 体出した", count);
LOG_WARN("HP が 0 未満になった: {}", hp);
LOG_ERROR("ファイルを開けない: {}", path);
```

書式は `std::format` と同じです。ログは Visual Studio の「出力」ウィンドウと、`logs/` のファイルに出ます。
`LOG_INFO` と `LOG_WARN` は開発用の構成 (Debug・Development) でだけ出ます。`LOG_DEBUG` は既定では出ません。

## 画面に線や形を出す

位置や範囲を確かめたいときは、`DebugDraw` で線を描きます。開発用の構成でだけ描かれ、Release では何もしないので、消し忘れても問題ありません。

```cpp
#include "DebugDraw.h"

DebugDraw::DrawLine(start, end, { 1.0f, 0.0f, 0.0f, 1.0f });       // 線
DebugDraw::DrawSphere(center, radius, { 0.0f, 1.0f, 0.0f, 1.0f });  // 球
DebugDraw::DrawAABB(min, max, { 0.0f, 1.0f, 1.0f, 1.0f });          // 箱
```

`Update()` か `Draw()` の中で、表示したい間は毎フレーム呼びます。「全体のデバッグ情報・設定」の「デバッグ描画」でまとめて ON / OFF できます。

## 値を画面に出す

確かめたい値は、`DebugGui()` で ImGui に出すのが手軽です。`DebugGui()` はエディター画面のときだけ呼ばれます。

```cpp
void Enemy::DebugGui()
{
    ImGui::Begin("敵");
    ImGui::Text("状態: %s", stateMachine_->GetCurrentStateName());
    ImGui::Text("HP: %d", hp_);
    ImGui::End();
}
```

ずっと調整に使う値は、[PropertyBinder](parameters.md) に登録すると保存もできます。

## 止めて見る

| 方法 | 内容 |
| :--- | :--- |
| 「全体のデバッグ情報・設定」の「一時停止」 | シーンの更新を止める。描画とエディター画面は動き続ける |
| 「時間 / パフォーマンス」のタイムスケール | ゲームの時間をゆっくり・速くする |
| デバッグカメラ (Y キー) | ゲームのカメラを動かさずに、好きな位置から見る。ゲームのカメラが映している範囲は黄色の線で出る |
| F1 | エディター画面を消して、実際のゲーム画面で確認する |

## 重いとき

1. 「全体のデバッグ情報・設定」で FPS を確認する。「描画リソース情報」で、モデルやパーティクルの数が上限に近づいていないかも見る
2. Debug 構成は遅いので、速さは Development で確かめる
3. GPU の時間を詳しく見るときは [PIX](https://devblogs.microsoft.com/pix/) を使う。描画の処理ごとに名前が付いているので、どこが重いか分かる

## Debug 構成で調べるもの

Debug 構成では DirectX 12 のデバッグレイヤーが有効になり、描画の使い方の間違いが「出力」ウィンドウに出ます。終了時には、解放し忘れた DirectX のオブジェクトも報告されます。
エンジンの描画まわりを改造したときは、Debug 構成で一度動かしてください。
